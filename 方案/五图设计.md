# 五图谱系视图设计

## 0. 设计结论

本项目的正式图谱入口设计为五个图：

- 本家主线
- 姻亲谱系
- 联姻桥接
- 后代分支
- 家族全景

最新结论：凡是和“某个人的位置”有关的图，都不能先画一张默认图再让用户在图上猜。必须先确定中心人物或根对象，再投影、裁剪、布局。也就是说：

- 第一次进入本家主线、姻亲谱系、联姻桥接、后代分支时，如果当前账号没有绑定人物，也没有上一次选择的中心人物，必须先弹出中心人物选择器。
- 图谱界面侧边或工具条必须常驻“中心人物”按钮，显示当前中心人物姓名；点击后可重新选择中心人物。
- 修改中心人物后，当前配偶、桥接家庭、后代根节点等派生参数全部失效，需要重新选择或由新中心人物重新推导。
- 中心人物相关视图只显示产品定义的“九族范围”之内的人物，超出范围的内容折叠成小分支入口，不直接塞进当前图。

`关系路径` 不放进这五个正式图里，而是作为全局工具面板存在。原因是关系路径回答的是“两个人是什么关系”，它更像一次查询结果，不适合作为长期停留的主图。任何正式图里点击“查看关系”时，都可以打开关系路径面板。

五图不是复用一套布局后换按钮文字，而是五种不同的数据投影。数据库保存完整关系，后端按视图返回限定范围，前端按视图使用对应布局器。这样可以避免当前出现的两个核心问题：

- 家族全景明明有 44 人，但仍按本家主线布局，导致大量人物被挤在视图边缘或视觉上像没显示。
- 家谱线明明应该是横平竖直，却被通用图布局和自动折线改成奇怪拐点。

## 1. 参考原则

本设计参考三类成熟谱系表达：

- GEDCOM 的 `FAM + CHIL` 思路：家庭不是简单的两个人互连，而是一个家庭单元连接伴侣和子女。项目里的 `FamilyUnit` 与这个语义一致。
- 传统 pedigree / family tree 的代际排布：老一代在上，新一代在下，同代人物在同一行，兄弟姐妹按顺序左右排列。
- genogram / pedigree 的线条语义：配偶横线，亲子竖线，兄弟姐妹共用水平分支线，复杂关系用线型或标记区分。

实现时不直接照搬医学家系图的性别符号，因为本项目需要保持当前黑金 UI 的人物卡片风格；但会继承其“代际成行、兄弟有序、家庭单元汇聚”的结构规则。

参考资料：

- FamilySearch GEDCOM 7.0 specification: https://gedcom.io/specifications/FamilySearchGEDCOMv7.html
- GEDCOM specifications index: https://gedcom.io/specs/
- FamilySearch GEDCOM tools: https://www.familysearch.org/en/gedcom/
- Merck Manual pedigree symbols: https://www.merckmanuals.com/en-ca/professional/multimedia/image/symbols-for-constructing-a-family-pedigree

## 2. 全局硬约束

### 2.0 中心人物先于图谱

五图不是“先拿一堆节点再布局”，而是“先确定观察者，再生成这个观察者能读懂的二维切片”。

中心人物状态：

```text
centerPersonId: string | null
centerPersonName: string | null
centerSource: account_binding | last_session | user_selected | route_param | demo
centerScope: nine_kinship | custom
```

首次进入规则：

- 如果登录账号绑定了 `person_id`，默认把该人物作为中心人物，并在工具条显示“中心人物：姓名”。
- 如果路由带了 `person_id`，优先使用路由人物，并把它写入当前图谱会话。
- 如果本地会话保存了中心人物且后端确认仍存在，可以继续使用。
- 如果以上都没有，进入中心人物相关视图前必须弹出选择器，用户选中真实人物记录后才请求图谱数据。
- 如果用户取消选择，画布不加载默认图，只显示“请选择中心人物”的空状态。

中心人物选择器不是自由文本提交框。输入框只负责搜索，最终必须选择一个已存在的 `Person`。如果要新增人物，应进入管理流程，不能在图谱入口临时创建虚假节点。

侧边按钮规则：

- 图谱工具条常驻“中心人物”按钮。
- 按钮展示当前中心人物姓名和范围摘要，例如“中心人物：张三 · 九族内”。
- 点击按钮打开同一个选择器。
- 更换中心人物后，清空 `selectedSpouseId`、`selectedFamilyUnitId`、`selectedRootId`，并重新加载当前视图。
- 更换中心人物后，如果当前视图缺少必要参数，例如姻亲谱系缺少配偶，则弹出对应选择器，而不是静默选择第一位配偶。

### 2.1 数据约束

所有视图都只接受后端明确返回的 `GraphViewResponse`，不在前端猜测缺失关系。

统一 DTO：

```text
GraphViewResponse
  view_mode: mainline | inlaw | bridge | branch | overview
  center_person_id?: string
  nodes: GraphPerson[] + GraphFamilyUnit[]
  edges: GraphEdge[]
  hidden_relation_count: number
  warnings: string[]
```

人物节点：

```text
GraphPerson
  id: string
  type: person
  name: string
  gender: M | F | U
  birth_date?: string
  death_date?: string
  is_alive: boolean
  badges: string[]
```

家庭单元节点：

```text
GraphFamilyUnit
  id: family:<familyUnitId>
  type: familyUnit
  family_type: marriage | partner | single_parent | unknown_parent | adoptive
  display_order: number
```

边：

```text
GraphEdge
  source: string
  target: string
  relation: partner | spouse | biological | adoptive | step | father | mother | parent
  style: solid | dashed | spouse | highlight
  metadata: birthOrder | displayOrder | relationKind | certainty
```

硬规则：

- `FamilyUnit` 是布局语义，默认不渲染成可见人物节点。
- 前端不根据姓名、性别、年龄推断父母或配偶。
- 前端不根据节点位置推断亲缘关系。
- 任何视图都不能显示莫名其妙的中间节点；家庭单元只能转为不可见锚点或短线交汇点。
- 人物方块默认只显示姓名；年份、生卒、职业等信息放到详情侧栏。
- 所有布局坐标必须由稳定规则生成，不能依赖接口返回顺序的随机性。

### 2.2 布局约束

正式家谱视图只允许四类线段：

```text
夫妻线：水平线
父母下行线：垂直线
子女分支线：水平线
子女上接线：垂直线
```

禁止：

- 禁止使用自动 `polyline` 寻路绘制正式家谱线。
- 禁止主线、姻亲、桥接、后代分支中出现长斜线。
- 禁止为了连接远端亲属跨越半张图拉线。
- 禁止把跨分支婚姻硬塞进当前主图；应显示徽标并提供“联姻桥接”或“关系路径”入口。

允许：

- 家族全景可以使用力导向或集群布局，因为它的目标是探索全部关系，不是正式阅读。
- 家族全景中的连线可以有轻微曲线或透明度差异，但人物卡片仍保持黑金风格。

### 2.3 视觉约束

沿用当前黑金 UI：

```text
背景：深黑、暗灰网格、轻微玻璃质感
人物框：深色半透明底、细金边、浅金文字
普通线：低亮暖灰/暗金
选中态：只高亮边框，不填充整块高亮
悬停态：只轻微提亮当前节点边框，不批量高亮全图
```

禁止：

- 红色人物框。
- 荧光蓝家谱线。
- 选中后整块黄色/白色填充。
- hover 后全图关系同时变亮。

### 2.4 交互约束

所有视图都支持：

- 鼠标滚轮缩放。
- 拖拽空白背景移动画布。
- 在人物节点上拖拽也能移动整体画布。
- 点击人物打开详情侧栏。
- 搜索人物后定位到该人物。
- `Esc` 或点击空白处取消当前选中态。

家族全景额外支持：

- 弹性拖拽。
- 节点轻微力导向避让。
- 按家族簇筛选。
- 按关系类型筛选。

### 2.5 顺序约束

所有视图的同级排序统一使用以下优先级：

```text
birthOrder
birthDate
displayOrder
name
id
```

配偶排序统一使用：

```text
spouseOrder
marriageStartDate
displayOrder
name
id
```

分支排序统一使用：

```text
branchOrder
最早出生子女 birthDate
家庭单元 displayOrder
familyUnitId
```

如果缺少排序字段，不在前端猜测，应使用后端返回的稳定兜底顺序，并在管理员诊断中提示“缺少出生顺序/展示顺序”。

### 2.6 九族范围定义

这里的“九族”不是直接套用古代宗法或刑罚语境中的九族。传统九族有多种说法，既有“上自高祖、下至玄孙”的九代说，也有父族、母族、妻族组合说。项目里必须使用可计算、可测试、男女双方对等的产品定义。

产品定义：

```text
中心人物九族范围 =
  上行四代直系祖先
  + 中心人物本人
  + 下行四代直系后代
  + 这些直系家庭单元内必要的配偶、兄弟姐妹和子女入口
```

对应传统九代轴：

```text
高祖辈
曾祖辈
祖辈
父母辈
本人
子女辈
孙辈
曾孙辈
玄孙辈
```

现代化规则：

- 父系和母系同等处理，不能默认只展开同姓父系。
- 配偶本人是连接节点，可以显示；配偶的原生家庭不自动算入本家主线，应进入姻亲谱系或联姻桥接。
- 中心人物兄弟姐妹可以显示；兄弟姐妹的深层后代默认折叠成支系入口。
- 父母的兄弟姐妹、祖父母的兄弟姐妹、外祖父母的兄弟姐妹默认不全量展开，只显示为旁支入口。
- 超过上四代或下四代的人物不进入中心人物相关视图的默认查询结果。
- 家族全景不受九族限制，因为它是索引和管理图，不是中心人物阅读图。

九族是最大候选边界，不是“全部铺开”的理由。各视图还要继续按自己的任务裁剪：

- 本家主线：只展开中心人物直系上下文和必要同辈。
- 姻亲谱系：只展开被选配偶的九族上下文。
- 联姻桥接：只展开两边各自的近亲局部，默认小于九族。
- 后代分支：只展开选中根的下行后代，深度可小于九族。
- 家族全景：显示全部或筛选后的索引，不按九族做默认裁剪。

### 2.7 小分支折叠模型

每个正式图下面都允许出现小分支，但小分支不能变成隐形全量展开。默认使用“分支胶囊”表达：

```text
BranchCapsule
  id: string
  type: branchCapsule
  title: string
  owner_person_id?: string
  root_family_unit_id?: string
  relation_to_center: string
  person_count: number
  generation_count: number
  preview_names: string[]
  target_view: mainline | inlaw | bridge | branch | overview
```

显示规则：

- 分支胶囊不是人物节点，不参与亲子线绘制。
- 分支胶囊只能用短连接线或虚线入口挂在相关人物附近。
- 胶囊文案必须说明它代表什么，例如“张二支系 · 18 人 · 3 代”。
- 点击胶囊后进入对应图，通常是后代分支或姻亲谱系。
- 展开胶囊时必须重新投影和重新布局，不能在当前主图上无边界追加节点。
- `person_count` 和 `hidden_relation_count` 必须来自后端，前端不能估算。

各图的小分支策略：

- 本家主线：兄弟姐妹后代、祖辈旁支、配偶原生家庭都显示为胶囊。
- 姻亲谱系：配偶兄弟姐妹的后代、当前人物本家显示为胶囊。
- 联姻桥接：左右两边远祖和旁支显示为胶囊，中间婚姻桥不折叠。
- 后代分支：超过深度、人数过多、重复出现的人物显示为胶囊或引用节点。
- 家族全景：簇可以折叠成家族卡片，点击后再展开为局部全景。

### 2.8 视图构建流水线

为了避免再次出现“44 人明明在数据库里，但图上像丢了”或“线条到处拐”的问题，所有视图按同一条流水线构建：

```text
resolveContext()
  确定 centerPersonId / spouseId / familyUnitId / rootId

fetchProjection()
  后端按视图和范围返回已裁剪数据

normalizeFamilyUnits()
  统一 Person - FamilyUnit - Child 语义

foldBranches()
  把非当前任务的旁支压成 BranchCapsule

measureSubtrees()
  计算每个家庭单元或子树宽度

assignGenerationBands()
  固定代际 y 层

assignLanes()
  按主线、配偶、旁支、胶囊分配横向轨道

generateGenealogyLines()
  只生成水平/垂直确定性线段

renderGraph()
  G6 只负责渲染和交互，不负责猜关系
```

禁止反向流程：

```text
先取全量图 -> 交给自动布局 -> 再想办法修线
```

这个流程是五图的底层防线。布局问题大多不是 CSS 问题，而是投影顺序错了。

## 3. 公共架构

### 3.1 后端分层

每个视图必须有独立 service 方法：

```text
get_mainline_graph(person_id, ancestor_depth, descendant_depth)
get_inlaw_graph(person_id, spouse_id, depth)
get_bridge_graph(person_id, spouse_id, depth)
get_branch_graph(root_type, root_id, depth)
get_overview_graph(scope, max_nodes)
get_center_candidates(keyword, limit)
get_center_context(person_id)
```

不能让五个按钮全部调用 `get_focus_graph`，否则会再次出现“图名变了，数据和布局没变”的问题。

`get_center_context(person_id)` 至少返回：

```text
person
available_spouses
available_family_units
default_mainline_depth
nine_kinship_summary
warnings
```

前端切换中心人物后先请求中心上下文，再决定当前图是否需要继续弹出配偶、家庭单元或根节点选择器。

### 3.2 前端分层

前端分四层：

```text
api/graph.js
  只负责请求对应接口

useGraphData.js
  保存当前 view_mode、图数据、loading、error

useGraphLayout.js
  根据 view_mode 选择布局器

FamilyGraphCanvas.vue
  只负责 G6 初始化、渲染、缩放、拖拽、点击
```

布局选择必须显式：

```text
layoutGraph(graph)
  if view_mode === mainline -> layoutMainline()
  if view_mode === inlaw -> layoutInlaw()
  if view_mode === bridge -> layoutBridge()
  if view_mode === branch -> layoutBranch()
  if view_mode === overview -> layoutOverview()
```

### 3.3 线条生成器

正式家谱视图共用一个线条生成器：

```text
addSpouseLine(leftPerson, rightPerson)
addParentStem(familyAnchor, busY)
addSiblingBus(minChildX, maxChildX, busY)
addChildStem(childX, busY, childTopY)
```

每条线都是 `type: line`，由不可见锚点连接，不能交给 G6 自动路由。

### 3.4 坐标不变量

正式家谱视图必须满足：

```text
同一代 y 相同
父母 y 小于子女 y
夫妻 y 相同
夫妻线 y 等于人物中心 y
单个子女时，父母中心 x 等于子女 x
多个子女时，兄弟分支线覆盖所有子女 x
父母下行线必须接到兄弟分支线
子女上接线必须接到人物框上边缘
```

家族全景必须满足：

```text
所有返回的人物节点都可见
FamilyUnit 不可见
初始 fitView 后所有人物在画布视口内
相同家族簇节点距离更近
不同家族簇之间有明显间距
拖拽后力导向不会改变数据库关系
```

## 4. 本家主线

### 4.1 目标

本家主线是普通用户默认入口。它回答：

```text
我或当前人物在本家血缘主线中的位置在哪里？
他的父母、祖辈、子女、孙辈是谁？
他的同辈和配偶在哪里？
```

它不回答：

```text
配偶的完整原生家族是什么？
所有旁支亲戚分别有多少后代？
整个数据库有多少人？
```

### 4.2 入口参数

```text
person_id: string
ancestor_depth: number = 3
descendant_depth: number = 3
include_siblings: boolean = true
include_spouses: boolean = true
include_spouse_origin: false
scope: nine_kinship
```

如果用户账号绑定了人物，默认 `person_id` 为绑定人物。否则首次进入本家主线必须弹出中心人物选择器。不能直接使用演示中心人物，除非当前运行模式明确是演示模式。

本家主线的中心人物就是全局 `centerPersonId`。切换中心人物后，本图立即按新中心人物重新加载。

### 4.3 后端投影范围

必须返回：

- 中心人物。
- 中心人物向上 `ancestor_depth` 代祖先。
- 中心人物向下 `descendant_depth` 代后代。
- 中心人物所在家庭单元。
- 中心人物子女所在家庭单元。
- 中心人物的兄弟姐妹。
- 祖先链上每个直系人物的配偶。
- 中心人物和后代的配偶。

默认不返回：

- 配偶的父母和兄弟姐妹。
- 兄弟姐妹的全部后代。
- 祖先兄弟姐妹的全部后代。
- 与当前主线无关的远端联姻家族。
- 超出中心人物九族范围的人物。

如果隐藏了关系，应增加：

```text
hidden_relation_count > 0
warnings: ["已隐藏 12 条旁支/姻亲关系，可切换到姻亲谱系或家族全景查看"]
```

### 4.4 前端布局

本家主线使用 `layoutMainline()`。

布局步骤：

1. 从中心人物向上找父母家庭单元，生成祖先链。
2. 从中心人物向下找子女家庭单元，生成后代树。
3. 每个家庭单元生成一个不可见锚点。
4. 祖先层在上，中心层在中间，后代层在下。
5. 直系链优先居中。
6. 同辈兄弟姐妹按顺序左右排列。
7. 配偶紧贴对应人物一侧，但不展开配偶原生家庭。
8. 已婚子女作为上层家庭的子女时，本人必须对齐父母下行主线，配偶放侧边。
9. 祖辈旁支、兄弟姐妹深层后代、配偶原生家庭全部优先生成分支胶囊。
10. 如果胶囊很多，按与中心人物的亲缘距离分组显示，不允许挤占主线代际层。

### 4.5 线条规则

夫妻线：

```text
人物 A 右侧锚点 -> 人物 B 左侧锚点
水平直线
```

父母到子女：

```text
夫妻中心点
  |
  |
兄弟水平分支线
  |      |      |
子女1  子女2  子女3
```

单个子女：

```text
夫妻中心点
  |
子女
```

不能为了单个子女额外画一条很短的水平 bus，否则会出现用户圈出的无意义拐点。

### 4.6 异常处理

多任配偶：

- 默认展示与中心主线相关的配偶家庭。
- 其他配偶家庭显示折叠徽标。
- 点击徽标可切换为对应家庭单元的后代分支。

未知父母：

- 不显示“未知父母”大节点。
- 只在人物上方显示一个小型虚线短柄或侧栏提示。

收养/继亲：

- 线型使用虚线。
- 详情侧栏说明关系类型。

循环祖先：

- 后端应阻断并返回 warning。
- 前端不能递归布局循环分支。

### 4.7 验收测试

后端测试：

- 给定中心人物，返回的 `view_mode` 必须是 `mainline`。
- 返回人物包含中心人物、祖先、后代、必要配偶。
- 不包含配偶原生家庭成员，除非他们也是中心人物血缘范围内成员。
- `hidden_relation_count` 等于被裁剪关系数。

前端布局测试：

- 人物节点 label 只等于姓名。
- 家庭单元不出现在可见人物节点中。
- 所有正式家谱边 `type === line`。
- 不存在 `type === polyline`。
- 夫妻节点 y 相同。
- 子女 y 大于父母 y。
- 单子女家庭不生成多余水平 bus。
- 已婚子女本人 x 等于父母下行线 x。

浏览器验收：

- 鼠标放到人物上，只当前人物边框轻微高亮。
- 点击人物后只边框高亮，不整块变亮。
- 拖拽空白区和人物区都能移动画布。

## 5. 姻亲谱系

### 5.1 目标

姻亲谱系回答：

```text
配偶来自哪个家庭？
配偶的父母、祖辈、兄弟姐妹是谁？
这个姻亲家庭与当前人物如何相连？
```

它不是把配偶全家塞进本家主线，而是以配偶为新的中心生成谱系。

### 5.2 入口参数

```text
person_id: string
spouse_id: string
depth: number = 3
include_spouse_siblings: boolean = true
include_spouse_sibling_spouses: boolean = false
scope: nine_kinship
```

如果没有全局中心人物，先弹出中心人物选择器。如果当前人物有多个配偶，必须再选择 `spouse_id`。不能前端猜一个。

如果当前人物只有一个配偶，可以默认进入该配偶的姻亲谱系，但工具条仍要显示“配偶：姓名”，并允许切换。

### 5.3 后端投影范围

必须返回：

- `spouse_id` 对应人物。
- 配偶向上 `depth` 代祖先。
- 配偶的父母家庭单元。
- 配偶的兄弟姐妹。
- 配偶与当前人物形成的家庭单元。
- 当前人物作为“联姻入口”。
- 二者共同子女，可默认显示一层。

默认不返回：

- 当前人物的完整本家祖先。
- 配偶兄弟姐妹的全部配偶原生家庭。
- 配偶家族中的远端联姻支系。
- 超出被选配偶九族范围的人物。

### 5.4 前端布局

姻亲谱系使用 `layoutInlaw()`。

布局步骤：

1. 把 `spouse_id` 作为视觉中心。
2. 配偶原生家族按本家主线规则展开。
3. 当前人物只显示在配偶旁边，标记为“联姻入口”。
4. 当前人物的原生家族折叠成一个小徽标，不展开。
5. 共同子女放在夫妻线下方。
6. 配偶兄弟姐妹与配偶同层排列。
7. 配偶兄弟姐妹的后代默认折叠为支系胶囊。
8. 配偶父母双方家族同等处理，不按姓氏偏向某一边。

### 5.5 视觉区分

配偶原生家族使用正常金色边框。

当前人物作为外来联姻入口：

```text
边框：偏暖金
徽标：本家入口
透明度：不降低
```

当前人物不能被画成灰色弱节点，因为他是连接两家关系的关键点。

### 5.6 线条规则

姻亲谱系的父母子女线与本家主线一致。

当前人物与配偶之间：

```text
当前人物 ---- 配偶
```

这条线必须是水平线。如果配偶与当前人物因布局不在同一层，应优先调整人物层级，而不是画拐线。

### 5.7 异常处理

配偶没有父母数据：

- 姻亲谱系仍可打开。
- 只显示配偶、当前人物、共同子女。
- warning 显示“该配偶暂未录入原生家庭”。

配偶有多个原生家庭单元：

- 生物父母家庭优先。
- 收养/继亲家庭以徽标展示。
- 管理员可在详情中选择主显示家庭。

当前人物不是配偶：

- 后端返回 400。
- 前端提示“请选择与当前人物存在配偶关系的人物”。

### 5.8 验收测试

后端测试：

- `view_mode === inlaw`。
- 返回配偶祖先与兄弟姐妹。
- 不返回当前人物完整祖先。
- 如果 `spouse_id` 非配偶，接口明确失败。

前端布局测试：

- `spouse_id` 位于主视觉中心区域。
- 当前人物与配偶 y 相同。
- 当前人物原生家庭不展开为人物节点。
- 共同子女位于夫妻线下方。

浏览器验收：

- 从人物详情点击“查看姻亲谱系”后，图谱明显切到配偶家族。
- 不出现两边家族无限展开。
- 不出现中间可见家庭单元节点。

## 6. 联姻桥接

### 6.1 目标

联姻桥接回答：

```text
本家和姻亲家是如何通过一段婚姻连接起来的？
两边各自的近亲结构是什么？
共同子女位于哪里？
```

它是双家族有限范围视图，不是全家族展开图。

### 6.2 入口参数

```text
person_id: string
spouse_id: string
depth: number = 2
include_children: boolean = true
include_siblings: boolean = true
scope: near_kinship
```

如果两人之间存在多个家庭单元，必须指定：

```text
family_unit_id: string
```

不允许前端自动选择其中一个家庭单元。

如果没有中心人物，先弹出中心人物选择器。如果中心人物没有配偶或伴侣家庭，桥接图不生成，显示“当前中心人物暂无可桥接的联姻关系”。如果有多位配偶，先弹出配偶/家庭单元选择器。

### 6.3 后端投影范围

左侧本家：

- 当前人物。
- 当前人物父母。
- 当前人物祖父母，深度由 `depth` 控制。
- 当前人物兄弟姐妹。

右侧姻亲：

- 配偶。
- 配偶父母。
- 配偶祖父母，深度由 `depth` 控制。
- 配偶兄弟姐妹。

中间桥：

- 当前人物。
- 配偶。
- 二者家庭单元。
- 共同子女。

默认不返回：

- 双方兄弟姐妹的完整后代。
- 双方兄弟姐妹配偶的原生家族。
- 超过 `depth` 的祖先。

### 6.4 前端布局

联姻桥接使用 `layoutBridge()`。

整体结构：

```text
左侧本家近亲        中间婚姻桥        右侧姻亲近亲

祖辈/父母                               祖辈/父母
    |                                       |
当前人物  -------- 家庭单元 --------  配偶人物
                    |
              共同子女分支
```

布局步骤：

1. 当前人物固定在中线左侧。
2. 配偶固定在中线右侧。
3. 二者夫妻线横跨中间，不经过其它节点。
4. 左侧本家局部树向左展开，但仍保持代际上下。
5. 右侧姻亲局部树向右展开，但仍保持代际上下。
6. 共同子女放在中间桥下方。
7. 左右两侧各自的父母线不能跨过中间婚姻桥。
8. 左右两侧超出默认深度的祖先、兄弟姐妹后代以胶囊挂在各自家族区域，不能跨到中间桥。

### 6.5 线条规则

中间桥：

```text
当前人物 ---- 配偶人物
```

共同子女：

```text
       当前人物 ---- 配偶人物
              |
          子女分支线
          |   |   |
```

左侧本家和右侧姻亲分别使用标准家庭线，但不能把左侧家庭线连接到右侧祖先，也不能把右侧家庭线连接到左侧祖先。

### 6.6 防拐点规则

联姻桥接最容易出现乱线，所以必须加硬规则：

- 中间婚姻线必须是水平直线。
- 当前人物和配偶必须强制同层。
- 双方父母家庭下行线只接到各自人物，不接到中间桥。
- 共同子女只能从中间桥中心下行。
- 如果两边局部树太宽，增加左右间距，不允许绕线。

### 6.7 异常处理

两人不是配偶：

- 不生成桥接图。
- 提示“这两人没有可桥接的配偶/伴侣家庭单元”。

一方没有原生家庭：

- 仍显示桥接图。
- 缺失一侧显示“未录入原生家庭”的折叠提示，不画未知大节点。

双方同属一个祖先家族：

- 不在桥接图里强行画回环。
- 显示“存在共同祖先，可查看关系路径”。

### 6.8 验收测试

后端测试：

- `view_mode === bridge`。
- 如果 `person_id` 和 `spouse_id` 不存在配偶关系，返回明确错误。
- 返回的左右两侧人物深度不超过 `depth`。
- 返回共同子女。

前端布局测试：

- 当前人物和配偶 y 相同。
- 当前人物 x 小于配偶 x。
- 中间婚姻线 `start.y === end.y`。
- 共同子女 x 落在当前人物和配偶中心之间。
- 左侧本家节点 x 不超过桥接中心。
- 右侧姻亲节点 x 不小于桥接中心。

浏览器验收：

- 画面一眼能看出“两家通过婚姻连接”。
- 中间不出现奇怪拐点。
- 共同子女线从夫妻中心向下。

## 7. 后代分支

### 7.1 目标

后代分支回答：

```text
从某个祖先或家庭单元开始，往下传了哪些后代？
某一支适合打印或导出时如何排列？
```

这是最接近传统纸质族谱的图。

### 7.2 入口参数

```text
root_type: person | familyUnit
root_id: string
depth: number = 5
include_spouses: boolean = true
include_spouse_origin: boolean = false
fold_after_depth: number = 4
scope: descendant_branch
```

如果从人物开始：

- 若人物有多个家庭单元，需要选择其中一个或显示多个分支。
- 默认从该人物的第一个主家庭单元开始。
- 如果入口来自中心人物按钮或本家主线，先列出中心人物相关的可展开家庭单元，让用户选择“看哪一支”。

如果从家庭单元开始：

- 直接以这个家庭单元为根展开。

如果没有中心人物也没有 `root_id`，后代分支不能加载默认空图，必须弹出根节点选择器。根节点选择器可以搜索人物，也可以从当前中心人物九族范围内的家庭单元中选择。

### 7.3 后端投影范围

必须返回：

- 根人物或根家庭单元。
- 根往下 `depth` 代所有后代。
- 每个后代的配偶。
- 每个家庭单元。
- 每条家庭单元到子女的关系。

默认不返回：

- 配偶的原生祖先。
- 与后代无关的旁支祖先。
- 远亲联姻另一侧家族。

### 7.4 前端布局

后代分支使用 `layoutBranch()`。

布局步骤：

1. 根家庭放在最上方。
2. 子女按出生顺序从左到右。
3. 每个子女下方递归展开自己的家庭。
4. 每个子女的配偶放在其右侧或左侧，保持同层。
5. 每个家庭单元形成一个独立子树。
6. 子树之间按照测量宽度留出间距。
7. 超过 `fold_after_depth` 的分支默认折叠。
8. 如果一代子女过多，先横向分页或折叠低优先级分支，不允许生成一条超长横线把整张图拉爆。

### 7.5 折叠规则

折叠节点不使用人物大框，而使用小型分支胶囊：

```text
张三支系 · 18 人 · 3 代
```

点击后：

- 展开该分支。
- 重新计算局部布局。
- 其它分支不自动收起，除非画布宽度不足。

### 7.6 重复人物规则

现实族谱可能出现远亲联姻，导致同一人物在后代分支中被多条路径命中。

规则：

- 第一次出现的人物渲染为真实节点。
- 第二次及以后出现的人物渲染为引用节点。
- 引用节点只显示姓名和“已在另一支出现”徽标。
- 不从引用节点继续递归展开，避免无限循环。
- 点击引用节点定位到真实节点。

### 7.7 线条规则

后代分支严格使用传统家谱线：

```text
父母横线
   |
子女分支水平线
 |   |   |
子  子  子
```

多代递归时，每个子树独立计算宽度，父母中心线对齐子女分支中心。

### 7.8 异常处理

根人物没有子女：

- 显示根人物和提示“暂无后代记录”。

某一代节点过多：

- 默认折叠低优先级分支。
- 提供“展开全部”按钮。
- 展开全部前提示可能导致画布很宽。

关系缺少出生顺序：

- 使用兜底排序。
- 管理员诊断提示“建议补充出生顺序”。

### 7.9 验收测试

后端测试：

- `view_mode === branch`。
- 返回人物全部为根的后代或后代配偶。
- 不返回配偶原生祖先。
- 深度不超过参数。

前端布局测试：

- 每个孩子 y 大于父母 y。
- 同一家庭子女按 `birthOrder` 从左到右。
- 折叠节点不会继续生成子树。
- 重复人物只展开一次。
- 所有正式边都是水平/垂直 `line`。

浏览器验收：

- 看起来像传统后代族谱。
- 分支很多时可以折叠。
- 不因为一个配偶家族把整张图拉爆。

## 8. 家族全景

### 8.1 目标

家族全景回答：

```text
当前数据库里到底有哪些人？
44 个人是否全部可见？
哪些家庭簇互相连接？
哪些人物孤立、重复或关系异常？
```

家族全景是管理员和高级浏览工具，不是传统纸质族谱。它允许比正式家谱图更多的自由布局和弹性拖拽。

家族全景不要求先选择中心人物。它可以在没有中心人物时直接打开，因为它回答的是“数据库有什么”。但如果当前已有中心人物，全景应高亮该人物所在簇，并提供“只看中心人物九族范围”的筛选按钮。

### 8.2 入口参数

```text
scope: all | demo | familyId
max_nodes: number = 300
cluster_by: rootFamily | surname | connectedComponent
show_edges: all | familyOnly | parentChild | spouse
show_issues: boolean = true
```

如果总人物超过 `max_nodes`：

- 后端不能静默截断。
- 必须返回 warning。
- 前端显示“已按筛选显示 300 / 1200 人”。

### 8.3 后端投影范围

必须返回：

- 范围内所有人物。
- 范围内所有家庭单元。
- 所有人物与家庭单元的 `PARTNER_IN`。
- 所有家庭单元到子女的 `HAS_CHILD`。
- 可选 `PARENT_OF` 和 `SPOUSE_OF` 冗余边。
- 异常摘要。

当前演示数据 44 人时，家族全景必须返回 44 个人物节点。任何少于 44 的结果都应被测试拦住。

### 8.4 前端布局

家族全景使用 `layoutOverview()`，不能复用 `layoutMainline()`。

布局目标：

- 初始状态所有人物可见。
- 相关家庭形成簇。
- 不追求所有线无交叉。
- 支持图数据库式弹性拖拽。

推荐算法：

```text
第一步：按 connected component 分组
第二步：每个 component 内按 rootFamily / surname 生成 cluster
第三步：cluster 之间使用网格或圆形初始排布
第四步：cluster 内使用带代际约束的 force
第五步：人物节点碰撞避让
第六步：fitView 显示全部人物
```

力导向约束：

```text
同一 FamilyUnit 的伴侣距离近
父母与子女保持中等距离
同一簇人物保持吸引
不同簇保持排斥
人物卡片不能重叠
拖拽某个节点只改变临时观察坐标，不写数据库
```

代际约束：

- 如果能计算出 generation，则同代 y 值接近。
- 如果存在循环或跨支联姻，不强制代际完全成行。
- 有 generation 的节点优先稳定，无 generation 的孤立节点放在旁侧。

### 8.5 视觉设计

家族全景仍使用人物方块，但可以缩小尺寸：

```text
正常缩放：姓名卡片
缩小很多：姓名首字或小点
放大：完整姓名和徽标
```

簇背景：

```text
张家父系：暗金轮廓
李家奶奶家族：暖灰轮廓
王家妈妈家族：茶金轮廓
孤立人物：红棕弱提示，仅管理员可见
```

连线：

```text
亲子/家庭线：暖灰
配偶线：暗金
异常线：管理员模式下弱红虚线
非当前筛选线：透明度降低
```

### 8.6 交互设计

家族全景工具条增加：

```text
筛选：全部 / 亲子 / 配偶 / 异常
分组：按家族簇 / 按姓氏 / 按连通分量
按钮：中心人物 / 只看中心九族 / 重排 / 适应视图 / 展开全部 / 只看异常
```

拖拽：

- 拖拽背景移动整个画布。
- 拖拽人物移动该人物，并带动邻近节点轻微弹性调整。
- 松手后节点缓慢稳定，不出现瞬移。
- “重排”按钮恢复自动布局。

点击：

- 点击人物打开详情。
- 点击簇标题可只看该簇。
- 点击异常徽标打开管理员诊断。

### 8.7 为什么全景允许交叉

全景的目标是“看完整结构”，不是“阅读正式族谱”。当所有人物、所有婚姻、所有亲子边同时出现时，二维空间中很难保证完全无交叉。强行无交叉会导致距离极远、线条更长、反而更难看。

因此：

- 本家主线、姻亲谱系、联姻桥接、后代分支追求横平竖直。
- 家族全景追求全量可见、分簇清楚、交互顺滑。

### 8.8 异常处理

循环祖先：

## 10. 五图状态机

前端视图状态：

```text
selectedView: mainline | inlaw | bridge | branch | overview
centerPersonId: string | null
centerPersonName: string | null
centerScope: nine_kinship | custom
selectedPersonId?: string
selectedSpouseId?: string
selectedFamilyUnitId?: string
selectedRootType?: person | familyUnit
selectedRootId?: string
centerModalOpen: boolean
parameterModalOpen: boolean
```

切换规则：

```text
first entry
  if selectedView requires center and centerPersonId is null -> open center modal
  if user cancels -> show empty guide, do not request graph

change center
  clear selectedSpouseId / selectedFamilyUnitId / selectedRootId
  reload current view if parameters are enough
  otherwise open parameter modal

mainline
  点击配偶 -> 可进入 inlaw 或 bridge
  点击某个家庭单元/后代入口 -> branch
  点击全景 -> overview

inlaw
  返回本家 -> mainline
  查看两家连接 -> bridge

bridge
  深入左侧 -> mainline
  深入右侧 -> inlaw
  查看共同子女 -> branch

branch
  点击人物设为中心 -> mainline
  点击配偶原生家庭 -> inlaw

overview
  点击人物聚焦 -> mainline
  点击簇 -> overview with scope
  点击异常 -> admin issue panel
  点击只看中心九族 -> overview with centerScope filter
```

如果切换目标缺少必要参数：

- 不能静默调用默认接口。
- 前端弹出选择器。
- 用户取消则停留在当前图。

如果切换中心人物导致当前图参数失效：

- 姻亲谱系：重新选择配偶。
- 联姻桥接：重新选择配偶或家庭单元。
- 后代分支：重新选择后代根。
- 家族全景：不强制重新加载，但更新高亮和“只看中心九族”筛选。

## 14. 最终验收标准

五图完成后，应满足：

- 普通用户默认看本家主线，结构清楚。
- 想看配偶家族时进入姻亲谱系，不污染本家主线。
- 想看两家怎么结亲时进入联姻桥接。
- 想看某一支传承时进入后代分支。
- 想看所有数据和异常时进入家族全景。
- 44 人演示数据在家族全景中全部可见。
- 正式家谱图横平竖直，无怪异拐点。
- 黑金视觉统一，没有红框蓝线。
- 悬停和选中状态克制，不全图高亮。
- 每个图都有明确测试，后续改动能被测试拦住。
