## 2. 执行命令

### 前端单元测试、构建与依赖审计

以下命令从项目根目录打开的新终端执行，不需要 Python 环境：

```powershell
cd front
npm ci
npm run test
npm run build
npm audit
```

`npm run test` 已包含 Vitest coverage；收集范围为 `src/tests/**/*.test.js`，包含 `src/tests/测试/`。覆盖率门槛在 `front/vitest.config.js` 中设置：lines、functions、statements 各 85%，branches 75%。覆盖率摘要生成于 `front/coverage/coverage-summary.json`。

姓名、完整拼音和首拼搜索模块可单独回归。以下用例覆盖检索规范化、管理人物/家庭/关系的真实组件过滤、关系路径 A/B 独立筛选及保留已选人物，并检查原管理 API 契约；拼音字段由后端统一生成，前端不另装拼音库：

```powershell
cd front
npx vitest run --config vitest.config.js src/tests/personSearch.test.js src/tests/relationPathSearch.test.js src/tests/managementComponents.test.js src/tests/managementApi.test.js
npm run build
```

模块命令不启用全局图谱 coverage；完整交付仍运行上面的 `npm run test`。

二维阅读可使用以下定向回归；完整交付仍需运行全量覆盖率和构建：

### 真实浏览器 E2E

先按 [部署指南](../deploy/README.md) 启动 PostgreSQL 并配置后端。后端终端从项目根目录执行：

```powershell
conda activate familytree
cd after
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开终端启动前端：

```powershell
cd front
npm run dev -- --host 127.0.0.1
```

巡检需要已有管理员账号，以及具有配偶和家庭分支的中心人物。空库应先按 README 完成显式初始化。巡检读取 `FAMILYTREE_E2E_PASSWORD`，未设置时读取根目录未跟踪的 `账密.txt` 中相应管理员密码；不要把真实密码写入测试脚本。设置好凭据后从项目根目录的新终端运行：

```powershell
cd front
$env:FAMILYTREE_E2E_PREPARE_DATA = '0'
npm run test:e2e:visual
```

默认不初始化账号或族谱。只有显式设置 `FAMILYTREE_E2E_PREPARE_DATA=1` 才会调用演示账号、数据库表和演示族谱初始化接口；已有迁移数据的验收保持为 `0`。浏览器页面除登录外拦截所有写请求，因此面板巡检只打开、读取、切换和关闭，不保存人物资料、不上传图片、不审批申请。

| 环境变量 | 用途 |
| --- | --- |
| `FAMILYTREE_E2E_URL` | 前端地址，默认 `http://127.0.0.1:3000`。 |
| `FAMILYTREE_API_URL` | 后端地址，默认 `http://127.0.0.1:8000`，需与前端代理指向同一后端。 |
| `FAMILYTREE_E2E_USERNAME` | 已有管理员用户名，默认 `admin`；自定义账号时显式指定。 |

| `PLAYWRIGHT_CHROME_EXECUTABLE` | 指定可用 Chromium/Chrome 路径；未设置时查找系统浏览器或使用 Playwright 浏览器。 |

## 3. 五图与几何约束

| 检查范围 | 当前契约与验证目标 |
| --- | --- |
| 本家主线 | 按中心人物及后端投影范围展示祖先、后代和家庭，中心上下文优先于过期的顶层中心字段。 |
| 姻亲谱系 | 根据指定配偶定位其原生家系，保留中心人物与配偶的连接。 |
| 联姻桥接 | 以明确选中的家庭连接双方原生家系，不将无关家庭充当桥梁。 |
| 后代分支 | 支持人物或家庭根对象；保留后代及其家庭连接。 |
| 家族全景 | 默认稳定归组为支系摘要，逐支展开人数守恒，全部展开恢复当前源图；真实连通分量独立排列。 |
| 父系阅读 | 仅明确生父且已确认的关系进入主干，按最短父系路径控制上溯代数；保留全部性别子女和近亲入口，多婚家庭均可补读旁支。 |
| 横纵方向 | 姓名不旋转，人物卡片仍为140×52；只改变坐标及世代轴，不能改变人物或事实集合。 |
| 人物唯一性 | 同一人物只绘制一张卡片，共同祖先、多次婚姻和生养家庭不能复制人物。 |
| 隐藏家庭单元 | `FamilyUnit` 作为家庭语义参与布局，不作为可见人物节点；不可见端点用于明确线段。 |
| 代际与卡片 | 亲子代际关系分层；伴侣分组不得将后代提升为祖先；人物卡片及折叠入口不重叠。 |
| 连线几何 | 使用显式水平、垂直 `line` 线段，避免穿过人物卡片；家庭各成员须通过线段实际连通。 |
| 独立通道 | 异家庭不能有正长度的共线重叠；代际留白按所需通道容量增加，密集图仍产生有限坐标。 |
| 交叉消歧 | 异家庭正交交叉形成断口，同家庭及共用人物真实端口不误标；仅渲染当前视口附近的标记，缩放平移后位置同步。 |
| 单子女与多子女 | 多子女共享水平兄弟线；单子女不产生虚假的兄弟线，但错位时仍有必要的水平连接段。 |
| 生养类型 | 生育、收养、继亲和未知关系分别保留；收养等类型使用虚线，不因共育关系虚构婚姻。 |
| 直接事实 | 没有对应家庭的直接亲子或配偶事实仍可布局，已由同类型家庭表达的关系不重复绘制。 |
| 循环与空图 | 异常亲子循环终止展开并保留关系证据和警告；空图不伪造本地族谱。 |
| 折叠入口 | 放在独立导航区域，保留目标视图与根对象；点击真实画布入口后加载对应图谱。 |

核心回归集中在 `front/src/tests/familyLayout.regression.test.js`，覆盖七人祖辈家庭、单子女姻亲、多配偶、不同生养关系、共同祖先、跨代婚姻、宽兄弟集合、密集无环家系、独立人物与异常循环，并验证输入顺序改变后的坐标稳定性。

## 4. 缩放、适配与交互

- 拖动画布、滚轮缩放、放大/缩小按钮、100% 恢复、适应视图、回到中心和缩略图导航均应操作当前真实画布。
- 手动缩放范围为 8%–250%；低于 45% 收起人物姓名，放大后恢复。人物卡片默认仅显示姓名，年份和生平在详情栏查看。
- 窗口大小变化保持当前倍率和视口中心对应的世界坐标；点击人物只更新详情与边框，不重置阅读位置。
- 画布获得焦点后，`+` / `-` 缩放、`0` 适应、方向键平移；悬停与选中只突出当前人物边框。
- 切换新视图时适配内容；较大的正式图优先显示可读的中心人物。相同视图刷新资料时保持选中或中心人物在屏幕上的位置。
- 移动尺寸下页面及资料、审批、关系路径面板不得超出视口或产生横向溢出。

浏览器脚本检查 390、768、1024、1280 像素宽度下的适配、倍率及观察位置，并记录画布节点重叠、斜线、穿卡片线段、内容边界与页面横向溢出等几何指标。

## 5. 会话、权限与资料维护

| 范围 | 验证目标 |
| --- | --- |
| 登录与恢复 | 登录设置 HttpOnly Cookie；刷新通过 `/api/auth/me` 恢复；本地用户信息和 `user_id` 参数不能冒充身份。 |
| 会话生命周期 | 服务端只保存随机凭据散列；重新登录旋转当前会话，退出撤销会话；过期和禁用账号立即失效；HTTPS 登录设置 Secure Cookie。 |
| 密码与注册 | 密码使用带盐 PBKDF2，历史 SHA256 仅在成功登录后升级；注册资料校验、待审批去重及审批后登录流程完整。 |
| 审批权限 | 普通用户不能读取待审批列表或执行审批；邮件 GET 仅显示转义后的确认页，POST 明确确认后才处理，同一申请不重复处理。 |
| 本人资料 | 只有管理员或账号已绑定的本人可修改职业、住址、名言、成就、生平，以及上传头像、照片；越权请求在写文件前被拒绝。 |
| 管理员结构维护 | 人物 CRUD、家庭属性及成员维护、独立亲子/配偶事实维护与诊断均要求管理员会话；普通用户保留只读浏览权限。 |
| 删除与来源 | 删家庭不删人物；显式独立事实、未标记历史事实和其他家庭仍支持的事实保留；仅删除失去全部来源的明确派生事实。 |

最终验收要求前端测试、构建、后端相关测试及浏览器 E2E 均通过。浏览器报告必须来自本轮运行，`findings` 为空，命令成功退出；截图数量和枚举用例数量取决于实际数据，不设历史固定值。测试覆盖率摘要、布局预览和浏览器报告属于运行产物，不作为源码提交。

## 8. PostgreSQL 迁移验收

迁移相关测试继续覆盖真实 SQLAlchemy Session 下的五图、路径、人物 CRUD、家庭关系派生、生养并存、删除外键、账号绑定、事务回滚与序列。迁移验收还需比对源快照的全部人物属性、家庭属性、关系数量、账号 ID、密码散列和人物绑定。
